# Multimodal UI evaluation, opentelemetry-demo, 2026-10-27

The scenario is `bench/scenarios/ui-eval.yaml`, committed in b535b0d before the run, and the runner is
`bench/ui_eval.py`.

**Task.** Is the product page `/product/OLJCESPC7Z` healthy, and if not, which part is wrong?

**Judges.** Both see the same captures and the same healthy reference:
- **Browser judge, no model:** new console errors, new failed requests, and images that did not load.
- **Visual judge:** both screenshots sent to Muse Spark 1.3. The mandate allows this
  (`models.screenshots_to_frontier`, set by David for this test environment), and every send is recorded by the
  egress gate.

| Condition | Browser judge | Visual judge |
|---|---|---|
| healthy ×3 | 3/3 healthy | 3/3 healthy |
| `adFailure` ×3 | 0/3 | 0/3 |
| `imageSlowLoad` 10sec ×3 | **0/3** | **3/3**: "You May Also Like product images missing" |
| `productCatalogFailure` (targeting on) ×3 | 3/3, naming `/api/products/OLJCESPC7Z` | 2/3 (one answer could not be read) |
| **Detection** | 6/12 | **8/12** |
| **Attribution** (degraded conditions) | 3/9 | **5/9** |

**Decision, by the rule fixed before the run.** The visual judge is better on both detection and attribution, so it
is integrated. When an anomaly opens, it judges the project's web page against a reference taken while the page's
own call path was healthy.

**Caveats**
- Twelve captures is a small sample.
- **`adFailure` never showed.** The ad banner was on the page in all three captures: the flag fails the ad service
  for a fraction of requests only. Both judges were right that the page looked fine, but the pre-registered
  expectation was "degraded", so both are counted wrong. Without those rows: browser 6/9 and 3/6, visual 8/9 and
  5/6.
- **The judges are complementary.** The visual judge sees blank images that the DOM reports as loaded; the browser
  judge names the exact failing request. Combining them is an idea for a next evaluation on new captures, not a
  result.
- **Cost.** About 700 to 1,000 completion tokens per visual judgement, mostly reasoning, and 20 to 60 s per call.

## End to end, in the autonomous watcher

- **Setup.** With the judge integrated, `unbidden watch` (autonomous) took its reference of the home page at
  14:00:28 UTC, while the page's call path was healthy.
- **Fault.** The operator turned `imageSlowLoad` on at 14:01:34.
- **Detection.** At 14:04:30 the watcher opened an anomaly, "the degradation starts in frontend-proxy" (latency),
  captured the page and compared it with the reference:
  - browser judge: "nothing differs";
  - visual judge: **"Hot Products images missing"**.

  The capture confirms it: the Hot Products images are blank.
- **Recovery.** The flag was restored at 14:04:54.

Metrics said where the latency was; only the visual judge said what a user saw.
