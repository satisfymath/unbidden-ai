# Campaign 12: Unbidden as an installed product on 39 repositories

Phase 5 report, 2026-11-03. Candidate `8686674` (wheel `a9154175…`), frozen at `83d2633` on 2026-11-01. Every number
below comes from `docs/bench/campaign12/eval/` (records per repository and run) and the ledger; the aggregate tables
with confidence intervals are in `eval/REPORT-aggregate.md` (generated by `bench/campaign12/report.py`). Results
are reported per class and the development class is calibration, not evidence: those 12 repositories shaped the
product. Nothing in code, wheel, harness, corpus or copies changed during the evaluation (23:48Z 2026-11-01 →
03:25Z 2026-11-03); two harness-only changes came after it and are named in §12.

**In one paragraph.** Installed from the wheel with no development environment, Unbidden set itself up, started,
refused a second start, stopped cleanly and served its dashboard on 39 of 39 repositories, at US$0 for Level A.
With real Meta models and maximum autonomy on twelve public campaign copies, it carried one change through the
whole chain on its own (pull request → the project's own CI on the exact head → merge only on green → deploy
with the team's steps → verified effect) on the one repository that had a lab and a rollback drill, and it did so
again in the second run but with a different outcome caused by a measurement rule, not by the change. Outside the
development class the funnel narrows sharply: of 8 independent repositories only misago received a pull request
(1 of 16 runs), because the product could not reproduce the project's checks in 11 of 19 independent
repositories (a sandbox image without `git`/`gcc`/`make`/`task`/`msgfmt`, requirement includes resolved against
the wrong directory, a container user without a home) and nothing is tried without them. Total model spend for
the campaign's evaluation: **US$2.10** (24 Level B runs; spoolman's two runs, appended after the first version of this report, cost US$1.26 of it, §11).

## 10. Defects and improvements, prioritized (general, with the evidence that found them)

**P1 — coverage and crashes**
1. **TOML datetime crashes `doctor`, `scan` and every agent job** (`observe/stack.py:368`, `json.dumps` of the
   parsed `pyproject.toml`; pipx `[tool.nab]`). One repository fully lost in three runs. Fix with `default=str` or a
   TOML-aware encoder plus a regression test on a pyproject with a datetime.
2. **Requirement includes resolved against the wrong directory**: the product writes `/tmp/unbidden-extra-0.txt`
   with `-r requirements.txt` (tracklater, oauthlib) and copies `requirements-*.txt` files without their siblings
   (dinkydash). Three independent repositories blocked. Resolve includes relative to the repository and copy the
   closure of `-r` files.
3. **Sandbox image without the tools the projects' checks need**: `git` (codex-lb, harlequin), `gcc` (conduit,
   archery), `make` (graphtage), `task` (rdflib), `msgfmt` (humanize). Seven repositories. The CI reader already
   knows what the team installs (`observe/ci.py`); provision the same in the deps image or classify the run as
   environment with the missing tool named (the codex-lb rule now does this for test-level failures only).
   *Corrected in phase 6 (2026-11-03):* Level A ran with the product's default mandate, whose package registries
   do not list `deb.debian.org`, so nothing from Debian could be installed there by design; conduit's and
   archery's records carry the product's own block naming that registry (correct behaviour, a mandate decision,
   not a defect), and humanize's `gettext` falls under the same rule. What stays the product's: the runner's
   baseline (`git`, `make`) is never installed even when Debian is allowed, an `apt-get install` after `&&` on
   the same line is not read, and a test command stopping at `X: command not found` is recorded as a bare
   `exit 127` instead of naming the program and what would provide it (`task` is installed by a CI action, not
   a registry: a declared gap, now said). Level B's mandate did allow Debian.

**P2 — the funnel after the checks**
4. **Host-load rule unfit for the host and misclassified**: `HOST_LOAD_MAX = 1.5` is an absolute 1-minute load on
   an 18-CPU machine whose idle load is 2.5–3; fst run 2 deferred the measurement for 900 s twice and then recorded
   "the candidate broke the workload: deferred: the host is busy", declined the opportunity ("2 experiments found
   no proven fix") and will not retry. Normalize by CPU count (or measure the sandbox, not the host) and keep a
   deferral a block, never a verdict about the candidate. This is why run 2 of fst produced no pull request.
5. **Candidate never run through the team's format/lint steps**: rich #12, #13, #18 red on `black --check` in
   every CI cell. The CI reader knows the lint packages; run them on the candidate before publishing and fix or
   drop the candidate.
6. **An experiment re-runs the whole suite on the base that `observe.checks` just measured, and an interrupted
   job restarts from scratch**: misago's 8977 tests take 58 min per side; run 2 spent 2 × 58 min on the base arm
   across the restart and published nothing. Reuse the baseline round for the same SHA and checkpoint per arm.
7. **Shallow F811 fixes** (alias the shadowed test): the fix lab should rename or delete a shadowed definition, or
   not propose; a verifier rule "the shadowed symbol is still never used" would catch it.

**P3 — honesty, environment, logging**
8. The PR body says a person decides even when the mode merges; say what the mode will do.
9. Sandbox identity: uid 1000 without a passwd entry (dooit), `/home/runner` read-only (mimirq).
10. Read the CI job's env and extras for the test command: `DJANGO_SETTINGS_MODULE` (mediacms), `--cov` without
    pytest-cov (python-mss), test files importing `scripts/` (reader).
11. Data services: readiness beyond 90 s (gymhero) and fixtures the tests expect (brightbean, recruitops,
    timetracker).
12. Provisioning errors truncated in the record (weblate's `RuntimeError:` with nothing after it).
13. The daemon's 5-minute map/connection refresh keeps the queue non-empty; a harness idle rule based on the queue
    never fires, and a product "nothing to do" signal would serve people too (status says "running", not "idle").

**Added after spoolman's two runs (2026-11-03)**
14. **P2 — one model call per HTTP handler to map endpoints to tables** (`world.endpoint_tables`): 81 of 92 calls in
    spoolman run 2, about US$0.45 of US$0.53, before any opportunity existed; 107 of 108 calls in run 1 the same
    way. Each call sends one handler and asks which tables it reads or writes. Batch handlers per call, derive the
    obvious cases statically (ORM models named in the handler), and cache by handler hash so a re-scan of an
    unchanged head costs nothing. This is the dominant cost on an API-rich repository and it is paid before the
    product has found anything.
15. **P2 — a spend block recorded as a measurement failure, and the monthly cap keyed by repository name**: run 2 hit
    the workspace's default cap (`maximum_monthly_spend_usd: 2.0`) because the cap sums the machine ledger by
    workspace *name* for the month, so the pilot's and run 1's spend on other checkouts of "spoolman" counted.
    The block surfaced as "not measurable: no workload was valid at the base after 5 attempts (lab.perf_request: no
    answer (SpendLimitReached …))", with the five attempts in the same second, and `research.consistency failed`
    repeated every tick; the record's `blocks` stayed empty. A spend limit is a block to show in status and the
    dashboard, not a verdict on the opportunity, and it should stop retries until the cap changes. Same family as
    P2-4 (keep a block a block). Whether the cap should follow the checkout rather than the name is a product
    decision; the default of US$2 is one run on a repository like this.
16. **P3 — API client extension rejected twice, consistency check never runs**: the forge built a client for
    `GET /api/v1/spool` (first attempt rejected: the read of 90 000 seeded rows timed out; second validated), then
    could not add `GET /api/v1/spool/group` because "a required parameter has no value to read with", twice, and
    abandoned the need; the reported-aggregates opportunity waited the whole run in both runs. The forge should
    take parameter values from the OpenAPI examples or from rows it already read, and page a large read instead
    of timing out on it.
17. **P3 — garbled reason on the whole-table-read opportunity**: "cannot measure: no the handlers of the endpoints
    that read it" (both runs). A missing noun in the message, and the underlying case (a table read whole by the
    seeded workload, not by any endpoint handler) deserves its own reason.

## 13. Release recommendation

Not a 1.0 and no automatic release. The installed product is dependable where it matters first: installation,
onboarding, lifecycle, dashboard, spend, and the safety rules under maximum autonomy held in 24 runs on public
copies. The value funnel on repositories the product did not grow up with is thin for reasons that are concrete
and general (§10 P1–P2), not architectural. Phase 6 should take P1-1, P1-2, P1-3, P2-4 (with 15, the same rule: a
block stays a block) and P2-5 with regression tests under `s12-dev`; 14 (mapping cost) is worth taking in the same
phase if it stays a bounded change, because it decides what a run costs on any API-rich repository. Then, phase 7 re-runs Level A on the 11 independent repositories blocked by P1 and Level B
on fst, misago, rich, spoolman and whichever of those repositories reaches a green suite, under `s12-confirm`. The next
candidate is judged on the same nine dimensions, per class, and claims nothing beyond that sample.
